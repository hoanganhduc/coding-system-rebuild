# Coding System Rebuild

> ⚠️ **Generated by an AI coding system — experimental.** Every file in this
> repository — code, configuration, and documentation — was written by the same
> multi-agent AI coding system that this repository backs up and replicates. It is
> **experimental**, built for one researcher's personal setup, and **may not work as
> expected** on other machines, other agent versions, or tasks outside the documented
> assumptions. See the [introductory blog post](https://hoanganhduc.github.io/misc/coding-system-rebuild/)
> for what it is and how to try it.

Backup/restore system for a complete multi-agent coding/research machine:
**Claude Code, Codex, GitHub Copilot CLI, OpenCode, CodeWhale + DeepSeek CLI,
Gemini/AntiGravity CLI, Grok, and OpenClaw**, plus the system layer they run on
(npm globals, Python environments, Docker images, systemd user services, cron,
shell environment, TeX Live, Calibre, Lean/elan, Rust/Bun toolchains).

```text
trusted restore-ubuntu.sh   signed encrypted recovery set   2 matching escrow shares
            \                         |                              /
             \________________________|_____________________________/
                                      |
                         one bare-host Bash command
                                      |
                         fresh Ubuntu 24.04 host
                             (amd64 or arm64)
```

Existing repositories are orchestrated as **pinned components**
(`components.lock`), not duplicated:

| Component | Role |
|---|---|
| [`openclaw-bot`](https://github.com/hoanganhduc/openclaw-bot) | OpenClaw slice: sanitized config templates, workspace skills, lifecycle scripts |
| [`ai-agents-skills`](https://github.com/hoanganhduc/ai-agents-skills) | Cross-agent skill installer (canonical skill bodies, per-agent targets) |
| [`vnu-eoffice`](https://github.com/hoanganhduc/vnu-eoffice) | VNU eOffice package and workspace integration |
| [`course_management_toolkit`](https://github.com/hoanganhduc/course_management_toolkit) | Classroom50 course management package and `course` CLI |

A private escrow repository (the owner setting `CSR_ESCROW_GH_REPO`) is not an
install component and does not contain the encrypted backup. It holds one
immutable Shamir share plus public generation metadata; the recovery set is
stored separately, and any two matching shares are needed to unwrap it.
Cloning the escrow repository alone restores nothing.

## Quickstart (fresh machine)

The recovery inbox must contain exactly one signed recovery-set directory and
exactly two shares from its escrow generation:

```text
~/secrets-restore-inbox/
├── restore-ubuntu.sh
├── csr-<set-id>/
│   ├── recovery-set.json
│   ├── recovery-set.json.sig
│   ├── recovery-signing-public-key.pub
│   ├── escrow-generation.json
│   └── *.gpg
├── escrow/<generation-id>/
│   ├── share-01.txt
│   └── share-03.txt
└── owner-data/                         # optional prior OpenClaw history/data
    └── openclaw-private-<utc>.tar.gz.gpg
```

```bash
/usr/bin/bash -p "$HOME/secrets-restore-inbox/restore-ubuntu.sh"
```

Before running that sole fresh-host command, make the inbox and its escrow
directories owner-only and the exactly two matching share files mode `0600`.
Prerequisites are a stock Ubuntu 24.04 `amd64` or `arm64` host, the ordinary
non-root owner account with noninteractive `sudo -n` access, working DNS/network
access to the locked package, Git, and image sources, and the complete protected
inbox above. Git, `gh`, Node/npm,
Docker, the agent CLIs, and their Python runtimes do not need to be installed
first; Stage 0 installs the bounded bootstrap substrate and the restore installs
the remaining locked closure.

Obtain `restore-ubuntu.sh` through a trusted, reviewed channel and retain it
with the recovery media. It pins the recovery signing public-key fingerprint,
verifies the signed set, installs the minimal Ubuntu bootstrap packages, checks
out the exact repository commit named by the set, and descriptor-executes the
sealed `bin/restore.sh` from that commit. It never runs downloaded shell text
through a pipe.

`make restore` is an internal Stage-0 continuation only; it is not a convenience
operator entry point and rejects a missing sealed snapshot/handoff. Resume a
failed recovery by rerunning the trusted `restore-ubuntu.sh` (optionally with
`PHASE=<n>`). `make install`
without a recovery set remains a developer/CI
**degraded mode**; it is not a complete machine recovery.

The same run restores native agent sessions and dedicated skill authorities,
regenerates per-runtime credential projections, pulls locked Docker image
digests, installs Codex's self-contained skill runtime, regenerates the
OpenClaw Bash completion, and reconciles host cron, user-systemd, and logical
OpenClaw schedules. See [SECRETS.md](docs/SECRETS.md) for the exact authority
boundaries and [INSTALL.md](docs/INSTALL.md) for the gated phase sequence.

A signed recovery set is only as complete as the source generation that
created it. After adding or migrating any newly declared authority (a
messaging, compute, model-provider, course or retrieval credential), publish the
reviewed repository commit and create a **new** recovery set. Rerunning restore against an older set cannot recover bytes that
were never archived.

## Routine use (source machine)

```bash
make backup    # refresh → sanitize → leak-scan → public commit
git show       # review what changed
make push      # leak-scans again, then publishes (always manual)
make secrets-pack # bind an immutable signed recovery set to published HEAD
make offsite   # immutable rclone upload + remote readback check
# bin/auto-backup.sh, run by hand (it is no longer scheduled), additionally refreshes
# an encrypted owner-data snapshot (research data/sessions/memory) via openclaw-bot/backup.sh
```

`make backup` is a source-machine backup path, not a public sharing package.
For a history-free export intended for external sharing, use:

```bash
PUBLIC_EXPORT_OUT=/tmp/coding-system-public make public-export
```

See [PUBLIC-EXPORT.md](docs/PUBLIC-EXPORT.md) for the allowlist, exclusions,
scanner exceptions, and verification rules.

For Grok, edit public implementation files in `~/grok-proxy`. Backup capture
mirrors only the manifest-allowlisted public source into `system/grok-proxy`;
private credentials and generated state stay outside that snapshot. Production
`grok-remote` still runs only from a qualified root-owned immutable release.

## Target matrix

| | amd64 | arm64 (origin) |
|---|---|---|
| Locked software/agent declarations | present | present |
| Clean-host release qualification | recorded in the active platform lock | recorded in the active platform lock |
| SageMath image | official digest | owner-built digest |
| Zotero Translation Server image | owner-built digest | official digest |
| Python environments | platform lock + qualification state | platform lock + qualification state |

The repository does not infer a green architecture from the other one. Read
`qualification.state` in each platform/Python lock and the local
`~/.local/state/coding-system/restore/restore-report.v1.json`; a pending lock is
not release-ready even when source-contract CI passes.

The restore is fail-closed on release artifacts. If the signed commit still
names a `pending-*` platform/Python lock or a `pending-publication` privileged
artifact, a full run reports `ARTIFACT_UNAVAILABLE` instead of downloading an
unlocked substitute or claiming success. At the time of this documentation
update, the checked-in Grok bootstrap and Python/platform qualification records
still require publication or clean-host promotion before the repository can
truthfully claim a complete full restore.

[vnthuquan](https://github.com/hoanganhduc/vnthuquan) (ebook discovery),
[vnu-eoffice](https://github.com/hoanganhduc/vnu-eoffice) (document monitor) — plus established
third-party software (Zotero, SageMath, Calibre, Lean, and the AI agent CLIs).
