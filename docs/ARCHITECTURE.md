# ARCHITECTURE

## Surfaces

`MANIFEST.yaml` defines ten scan roots. A top-level entry under a root that no
manifest entry classifies is an orphan: it is never captured, and `make sync`
lists it as a warning until it is classified. The table combines
`.codewhale`/`.deepseek` for readability and lists `~` extras separately because
they are explicit rootless entries, not an additional scan root:

| Root | Agent / role | Public part | Private part | Excluded |
|---|---|---|---|---|
| `.claude` | Claude Code | settings/mcp templates, CLAUDE.md, hooks, docs, templates, instructions, commands, agents, rules, skills (real files) | secrets.json, .credentials.json, memory, learnings, zotero/calibre config | sessions, caches, projects, data symlinks |
| `.codex` | Codex | config.toml template, AGENTS.md, agents, hooks, skills, get-shit-done | auth.json | runtime, sessions, logs (~8GB) |
| `.copilot` | Copilot CLI | config/settings/permissions, agents, skills, ide | mcp-config.json | session-state, logs |
| `.config/opencode` | OpenCode | jsonc, AGENTS.md, agents, commands, skills, package(+lock).json | — | node_modules, opencode.db |
| `.codewhale` + `.deepseek` | CodeWhale/DeepSeek | config templates (key-redacted), AGENTS.md, mcp.json, agents, skills, tools | config.toml (full), secrets/, memory, learnings | snapshots (8.6GB), sessions |
| `.gemini` | Gemini/AntiGravity | GEMINI.md, config, settings/keybindings/skills/plugins/builtin | oauth token | brain, cache, conversations, bin |
| `.ai-agents-skills` | installer state home | — | — | all (regenerated by installer) |
| `.config/systemd/user` | services | unit templates + `units.state` | — | wants/, *.bak |
| `.local/bin` | wrappers | 7 hand-written wrappers | — | pip console scripts, ELF binaries |
| `~` extras | shell | sanitized bashrc/profile/npmrc | `.secrets.env` | — |

`~/.openclaw` is **delegated**: its public sync/install belongs to the
`openclaw-bot` component (REBUILD-MANIFEST.json). Its SECRET files are still
owned by this repo's secrets manifest (single-zip principle).
Skill SKILL.md symlinks are **delegated** to the `ai-agents-skills` installer.
The `research_compute` GHA/Modal broker is **delegated** too — its code installs to the
runtime root (not captured); only its per-install `research-compute.toml` rides the zip.

## Manifest semantics (`MANIFEST.yaml`)

- classes: `public-copy`, `public-template`, `private-archive`, `exclude-*`, `delegate`
- first-match-wins at file level, manifest order matters
- template verbs: `home-substitute` (`/home/<user>` ⇄ `{{ HOME }}` — applied to
  ALL public text files), `key-redact` (named keys → `{{ KEY }}`),
  `secret-env-split` (bashrc managed block), `emit-keys` (key names only)
- invariants enforced by the engine: symlinks never copied (recorded against
  `system/symlinks.tsv`), ELF binaries refused in public classes, nested
  `.git` dirs never captured, zero `/home/<user>` literals survive rendering,
  private paths cross-checked against the secrets manifest
- `global_exclude` globs never enter a public class (backup leftovers, skills
  synced from an account, vendor skill bundles); databases, histories,
  sessions, feedback drafts, installation IDs, owner/tunnel records and paths
  holding `{{` are refused in public classes, and so are binary files other
  than images and fonts, anything the leak scan does not read (`node_modules`,
  files over 20 MiB), any file holding a private denylist entry, and captured
  content carrying the scanner's `LEAKSCAN-EXEMPT` marker outside authoritative
  mirrors
- `*.template` outputs carry `{{ EMAIL }}` and `{{ <KIND>_ID }}` placeholders
  instead of email addresses and identifier values
- the rendered tree must pass `bin/leak-scan.sh`: `make sync` reports the
  verdict, and `sync --apply` renders into a private stage and publishes
  nothing unless that scan passes, the private denylist is present, and every
  entry, the entry order, `global_exclude` and the scanner's exceptions match
  the owner review in `MANIFEST.review.json` (`bin/review-manifest.py` lists
  pending items; approval is interactive, a process control rather than a
  security boundary)

## Leak scanning (4 layers, fail-closed)

1. generic patterns (token prefixes, JWT, PEM, AWS, telegram-token shape,
   40-hex with public-hash context exemptions, home paths)
2. secret KEY NAMES followed by literal values (placeholders allowed;
   `/tests/` fixture paths exempt from this layer only)
3. private denylist `~/.config/coding-system/leak-denylist.txt` (low-entropy
   personal IDs; ships in the zip; also consumed by openclaw-bot's redaction);
   `CSR_REQUIRE_DENYLIST=1` makes a missing denylist a finding
4. identity-bearing classes (`bin/lib/leak_scan_extra.py`): real-looking
   email, home paths of any user, UUIDs, long numeric IDs, identifier fields,
   tailnet names, Tailscale CGNAT addresses, phone numbers, `.onion` and tunnel
   host names; it also reads UTF-16 text and zip members

Findings print as `file:line` only; matched values are never shown. The
private pre-push gate (`system/git-hooks/pre-push`, installed with
`make install-git-hooks`) checks new commits' metadata and added lines before
any push.

Canaries are constructed at runtime by `tests/leak_scan_selftest.sh` — nothing
token-shaped is ever committed.

## Components (`components.lock`)

`name=https-url@ref`; `ref` is a commit SHA after publish, or
`LOCAL:~/path` before publish (then `external/<name>` symlinks the live
checkout). `make components LOCAL=1` forces live mode. ai-agents-skills keeps a
compatibility/object repository at `~/ai-agents-skills`; an existing development
worktree is not checked out or cleaned by restore. Phase 8 derives only the exact
pinned Git object. Before any materialization call, it binds the exact
materializer bytes through an opened descriptor and SHA-256 gate into a read-only,
content-addressed, no-replace helper owned by the user; later calls never execute the
mutable checkout path. It then verifies every raw blob and executable class and
publishes the stable execution/reference authority at
`~/.local/share/coding-system/components/ai-agents-skills/<sha>`. ai-agents-skills
never uses root: no step of its install or runtime runs under sudo. Other
components live under `external/`. The umbrella owns
docker images and systemd rendering; openclaw-bot's `install.sh` is invoked
with `--skip-docker --skip-services` so there is exactly one writer per surface.

## Symlink topology

`system/symlinks.tsv` is the canonical list (verification + recreation):
`.claude/.local → .openclaw/workspace/.local` (shared python env),
`.claude/data/{research,runs,job-queue} → workspace data`,
plugin-skills → npm-global openclaw dist, `zot → workspace zotero/zot.py`,
research-skills-venv → `~/.venvs`. The old `agents/sandbox → agents/main`
alias is not recreated: no agent is named `sandbox`, and the pinned
openclaw-bot refuses links in `~/.openclaw/agents` (its auth migration
removes a relative alias of that kind).
`/usr/local/bin` links (sudo) live in `system/bin/usr-local-bin.tsv`.

## Python environments (rebuilt, never archived)

All seven venvs are installed offline from a digest-selected OCI wheelhouse and
canonical manifests. Six live under
`~/.local/share/coding-system/python-closure/`; the workspace venv lives under
the mounted OpenClaw workspace so its relative `.local` projection also works
inside the sandbox. The old freeze files are capture evidence, not restore
inputs. See `docs/PYTHON-CLOSURE.md` for the qualification and provenance chain.
